Audit the auditors (monthly, or on demand): $ARGUMENTS (default: sample the last month of docs/reviews/ + manager entries in docs/decisions.md).

_This is the **periodic, cross-run** quality audit that samples history. It is distinct from the **per-run** integrity audit the Manager performs at the end of every `/maat:ship` (did each agent in this one run leave a dated report with evidence, run real checks, do its ADR check). This command grades the quality of that accumulated work over time._

0. **Start from the numbers, not from a hunch.** Run `node docs/dashboard.mjs`, `node docs/run-log.mjs --summary --since <the period you are auditing>` and `node docs/receipt-check.mjs --since <same date>`, then read the dashboard's **Agent performance** and **Manager decisions** panels. They give you, mechanically: per-agent finding volume, the share of each agent's findings backed by executed evidence rather than reasoned from a document, how often it ran nothing, how often its receipt did not hold up and had to be reopened, and how often its HIGH was triaged down as over-called. Use that to CHOOSE the sample below — audit the agents the numbers point at, not a random six. State the figures you started from, so the next audit can tell whether anything moved. `receipt-check` adds the other half: which past reports still fail their own mechanical triggers today — a checksum that never balanced, a `[HIGH]` resting on `derived` evidence, a `[HIGH]` with no stated exposure, a finding with no bug Issue filed. A report that was greenlit at the time and fails the check now is the highest-value sample in the period, because it is a miss the loop did not catch. If none of these files exist yet, say so and sample by hand.
1. Sample up to 6 artifacts across ALL authors (every reviewer type + manager decisions — nobody is exempt).
2. For each, grade with evidence: Evidence quality (claims verified vs asserted; raw output present?) · False-positive rate (findings that were wrong/invented requirements) · Softening (findings downgraded without evidence) · Missed blockers (found later but visible then) · PRINCIPLES.md compliance (finding count discipline, unlock-naming, tone) · **Receipt fidelity** — for a report carrying a `RECEIPT:` block, does it actually match the body above it (every `[ISSUE]`/`[SUSPICION]` in the body surfaced as a highlight, counts add up, verdict not softer than the findings support)? The Manager's day-to-day audit trusts this block on STANDARD tier instead of reopening the file — a receipt that quietly undersells its own report is the exact failure mode that trust depends on not happening, so grade it accordingly and name the reviewer if it drifts.
3. Output a per-auditor credibility scorecard (IMPROVING / STEADY / DEGRADING + the single behavior to change), and one process finding: where did ceremony exceed risk, or risk exceed ceremony, this month?
4. Persist to docs/reviews/meta-audit-<YYYY-MM-DD>.md + REVIEW_LOG row. The manager reads the scorecard; the human reads the process finding. Recursion stops here by design: meta-audits are themselves sampled only by the human.
